The Datatypes of Datalit

Datalove's datatypes, their representation, and semantics are focused on correctness and completeness, particularly with regard to tricky corner cases related to subjects like overflow, NaNs, etc; and we take some difficult positions.

Datalit types are subtypes of Datafun types, and have a dedicated declarative syntax suitable for serialization and configuration.

Datalit types are:

  • Unit, (), also a zero-element anonymous tuple.
  • Booleans, bool - true and false
  • Fixed integers, u8, u16, u16, u32, u64, i8, i16, i16, i32, i64
  • Big integers, int
  • Floating point numbers, f32
  • Anynomous tuples
  • Anonymous structs
  • Anonymous enums (ADTs)
  • Lists, list<T> - contiguous, growable, heap-allocated arrays
  • Maps and Sets map<K, V> and set<T>
  • Tensors, tensor<T> - multidimensional arrays
  • Optional types, ?T
  • Result types, !T - which may either hold T or error
  • Existential data types, data - dynamically-typed and pointer-packed version of any of the above
  • Existential error types, error - dynamically-typed and pointer-packed version of any of the above

Datalit types are value types and stored inline. Datalit structs and enums are structurally-typed.

Unit

Spelled (), which can also be considered a zero-element anonymous tuple. This is the implicit return type of void functions.

Note that {}, the empty anonymous struct, has identical representation, but is not used as the unit type.

Booleans

The bool type has two values, true and false.

let a: bool = true
let b: bool = false

Booleans are used in if and else if conditions.

require sys/core/debug

let a = true
let b = false
if a
  debug.print("a")
else if b
  debug.print("b")
else
  debug.print("other")
end if

Booleans support logic operators and, or, xor, implies and not.

let a = true
let b = false
let c = a or b
let d = a and  b
let e = a xor b
let f = a implies b
let g = not a

implies being logical implication, rarely given a first-class operator but common in logic:

| a | b | a implies b | |-------|-------|-------------| | false | false | true | | false | true | true | | true | false | false | | true | true | true |

Fixed integers

Standard fixed integers, u8, u16, u16, u32, u64, i8, i16, i16, i32, i64; these are efficient and inlineable, but because Datalove cares insists on numerical correctness, must be used with checked operators to deal with overflow:

fun add_result(a: u16, b: u16): !u16
  let c = a +! b // early-return error on overflow
  ret ok c
end fun

fun add_option(a: u16, b: u16): ?u16
  let c = a +? b // early-return option on overflow
  ret some c
end fun

Unsigned fixed integers support +?, -?, *? and /? checked-option binops, and +!, -!, *! and /! checked-result binops. Signed fixed integers additionally support unary negation, -? and -!.

The "bare" math ops are supported but widen to int.

fun add(a: u16, b: u16): int
  ret a + b
end fun

This compromise allows for convenient but inefficient math in the repl and scripts, while modules are expected to be more careful with overflow.
